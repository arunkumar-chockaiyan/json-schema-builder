A walkthrough of the JSON Schema Builder running at localhost:5173: browsing the commerce family, reading the example-driven DSL used to author the order schema, and wiring a new billingAddress field to the existing address component so it resolves, validates, and generates examples automatically.

01

Open the registry, pick a family

The registry lists schema families. commerce is the only one defined here, holding orders, carts, and the shared building blocks between them.

localhost:5173
02

See what a family is built from

Inside commerce: a locked base.schema.json that merges into every schema (id, createdAt, tenantId, region, details), three reusable components — address, contact, shippingInfo — and three concrete schemas: invoice, order, report.

localhost:5173/families/commerce
note base fields cascade to every schema in the family the moment the base changes.
03

Author the order schema by example

Instead of hand-writing JSON Schema, you write an annotated example. Trailing comments like -- required, -- text for descriptions, and comma-separated values for enums drive the generator. One directive matters here: -- component: <name> links a field to an existing component instead of inferring its shape from the example.

order · Input
added "billingAddress": {} -- component: address; required
04

Apply it, and the link shows up as structure

Clicking Apply re-derives the schema. The Constraints tab confirms billingAddress landed in both places: the required-fields list and, separately, the component-links table alongside the two links that were already there (shippingInfo, contact).

order · Constraints
05

The example generator proves the link resolved

Switching to the Examples panel and generating a full instance shows billingAddress expanded to the component's actual shape — line1, city, postalCode, country, unit — the same fields already visible under contact.address, without redefining any of them.

order · Examples
06

The registry now tracks the new dependency

Back on the address component itself, the "used by" banner has picked up the new caller: it now reads component:contact, schema:invoice, schema:order, schema:report — the link is registered at the family level, not just resolved locally inside one schema's view.
